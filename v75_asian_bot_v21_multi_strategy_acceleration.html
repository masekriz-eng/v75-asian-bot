Asian Directional Bot — Multi-Strategy Acceleration Research — v21

Research build v21. Current Deriv public market-data WebSocket + authenticated account trading stream for Demo or Real Options accounts. One ASIANU/ASIAND trade at a time. Core direction requires Price vs previous-5 SMA + SMA slope + Momentum 3 to agree 3/3. SMA-side persistence is a configurable anti-noise filter. Directional normalized distance and normalized SMA slope are recorded for research; volatility and acceleration remain contextual, not hard filters. Volatility is contextual only. Rolling win rate is advisory in BALANCED mode. Winning-streak persistence affects sizing only. Loss progression and loss-streak protection are separate risk controls.

Deriv account connection
Account mode: DEMO. The bot will request a Demo-scoped authenticated WebSocket.
Strategy & entry settings

V21 research design: every qualifying setup is evaluated under the same future 5-tick Asian settlement window. We compare five approaches: A) Technical baseline (follow the 3/3 technical direction), B) Acceleration-confirmed (trade technical direction only when acceleration strengthens it), C) Acceleration-reversal follow (trade technical direction when acceleration weakens/reverses), D) Contrarian exhaustion (trade opposite technical direction when distance is large and acceleration reverses), and E) direct opposite-direction control and F) deterministic random control. Live strategy selection controls which candidate, if any, is actually traded. The default is flat $0.35 validation with no money management.

Rolling win rate & streak persistence
SMA side persistence is an entry-quality filter; normalized slope and signed distance are recorded for research only. Persistence is direction-specific: UP→UP→UP is an UP streak; DOWN→DOWN→DOWN is a DOWN streak. Changing direction resets the current winning streak for sizing. The persistence statistic is P(next win | N prior same-direction wins).
Loss progression — adjustable

Next-trade stake after L consecutive losses = min(base × factor^min(L,max level), cap). Set the factor to 1.00 for flat staking. A win resets the loss progression to base.

Loss-streak protection

Research samples: every configured number of ticks, when no live trade is active, the bot captures the current setup and later settles the selected strategy, technical baseline, opposite direction, continuation candidate, exhaustion candidate and deterministic random-control direction on the same future tick window. This is research-only.

Cooldown records: when cooldown protection is active, each qualifying signal is recorded as a paper trade by default. It is never sent to Deriv, never changes rolling WR or streak state, and is settled after the configured paper duration using the Asian Up/Down rule (exit tick versus the average of the contract-period ticks).

Connection resilience: both WebSockets send a keepalive ping every 25 seconds. If the idle authenticated trading socket drops, the bot automatically reconnects up to 3 times before stopping. If a contract is active when the trading socket drops, the bot stops safely and never opens a replacement trade.

The base entry rule follows the selected core confirmation mode + selected numeric distance threshold. After 2 losses, protection upgrades the core requirement to 3/3 + distance. After 3 losses, Momentum 5 must also agree. At 4 losses, trading pauses until 5 distinct valid signal events have appeared. At 5 losses, the session stops. When Session target profit is above $0, the bot stops opening new trades once cumulative session P/L reaches the target. The currently open contract is allowed to settle normally.

Optional warm-start history

Imported records are used only for rolling WR and persistence calculations. They are stored by market. Historical records from a different strategy are not proof of current behavior.

Account safety: select DEMO or REAL deliberately. REAL mode requires the explicit arming checkbox before START. The PAT is used only in page memory and is never written to localStorage. Market data is read from a separate public WebSocket; trading uses an authenticated account-scoped WebSocket for the selected account. If either connection drops, the bot stops rather than opening another trade.
Decision flow: technical core → SMA persistence → selected live strategy → WR/protection checks → at most one directional trade. Every research sample evaluates technical baseline, acceleration-confirmed, acceleration-reversal-follow, contrarian exhaustion and random-control directions on the same future Asian settlement window. Research outcomes never place extra contracts or affect account P/L.
