Survival allocation—
Probability-conditioned sequence learning: the KNN remains the primary directional engine. After every normal trade, the learner records the pre-sequence model probability, its probability bucket, the current W/L sequence, the model direction, and the actual result. It learns which sequences work at which probability levels instead of assuming a 60% signal behaves the same as a 65% signal. The strongest available evidence is selected hierarchically: exact sequence + probability bucket + direction → sequence + probability bucket → probability bucket + direction → probability bucket → legacy sequence-only fallback. Two-sided recovery legs are excluded.
RISE/FALL sequence learner: this is a separate directional sequence model. For normal trades, it reconstructs the actual market direction from Entry/Exit (or from Direction + Result when prices are unavailable), then learns 1–4 direction patterns such as R, F, RR, RF, FR, RRR, RFRF. Imported CSVs use Mode = NORMAL rows only, so two-sided recovery legs are excluded. The sequence model can gently adjust the KNN P(RISE)/P(FALL); it never replaces the KNN direction by itself.
Model discipline: the edge gate validates the core KNN out-of-sample against a known random-walk null. The W/L sequence and RISE/FALL sequence layers remain secondary overlays; passing the gate does not prove those pattern layers contain a true edge.
Statistical edge validation: the bot first tests the directional KNN on a chronological out-of-sample set, measures return-sign dependence, and runs the same KNN walk-forward process on known random-walk paths generated from the configured annual volatility. In REQUIRE VALIDATED EDGE mode, normal live entries are blocked until the real OOS result is above the configured break-even margin and the real result beats the null benchmark at the configured percentile. This version treats technical/sequence patterns as hypotheses, not proof of an edge.

Two-side recovery: after every normal-trade loss, the bot opens RISE + FALL. The current model-favoured side receives the configurable recovery factor; the non-favoured side stays at base stake. After the pair settles, the next normal trade is at base stake. A normal WIN exits reset mode; a normal LOSS starts another two-sided recovery pair using the new current model signal.
Calibration bootstrap: until a probability bucket has enough out-of-sample observations, the model preserves most of the current signal instead of collapsing it toward 50%. This prevents a cold-start "zero trades" condition while empirical calibration builds.
The survival engine treats the sequence-loss budget as the hard risk boundary. After a loss it calculates the payout-aware recovery stake, then caps that stake so the remaining sequence budget is still sufficient to absorb the configured number of consecutive losses. A win resets the sequence. Session profit/loss limits remain separate hard stops.

Entry logic: Market ticks use a dedicated public WebSocket; trading uses a separate authenticated WebSocket. Both connections are monitored and automatically reconnected while the session is active. SMA(5) slope + Momentum 3/5 + normalized distance + acceleration + volatility → KNN P(RISE)/P(FALL) → walk-forward calibration → choose higher-probability side → request a live Deriv proposal → calculate actual payout → enter only when probability and payout pass the configured thresholds. After a loss, the survival engine computes the stake needed to recover the accumulated loss plus the recovery target at the live payout, then caps it against the remaining sequence-loss budget, configured budget cap, and hard USD cap. For ordinary trades it never forces an opposite direction; the model still chooses the direction independently. After the loss-streak trigger, the dedicated two-side reset intentionally buys both directions at the base stake.

Stable connection layer: market and trade sockets are independent, trade OTP is renewed on reconnect, subscriptions are restored, heartbeats are monitored, open positions are reconciled after trade-socket interruptions, and the sequence-loss budget is entered directly by the user for the risk engine. V2.12 keeps the same 9 scale-normalized model features and walk-forward outcome embargo from the uploaded V2.9.1 base. V2.24 keeps the V2.13.1 prediction layer, the V2.16 two-side execution layer, and adds an online live-trade sequence learner: neighbor agreement is diagnostic only; raw KNN confidence is softened, calibrated against walk-forward outcomes without sparse-data collapse, capped at 72%, lightly balanced against the recent directional base rate, and tempered by a soft mean-reversion regime when price is extended. These adjustments never force the opposite direction during ordinary entries.
